# WIKI: модуль импорта документов в базу знаний (doc-линия агентной сети)

Единая инструкция: что делает модуль, зачем каждый шаг, где дашборды,
как посмотреть содержимое базы, как обновлять/удалять/резервировать.
Смежные документы: RAG-GUIDE.md (методика RAG и регламент КР), AGENT-NETWORK-PLAN.md (роли/оркестратор).

---

## 1. Что это и зачем

Модуль превращает «бумагу» организации (приказы, КР, регламенты, сканы) в
**машинно-поисковый корпус с цитируемостью**: сотрудник задаёт вопрос в чате →
система находит куски документов → модель отвечает **только по ним**, со
ссылкой `[имя_документа#чанк]`. Зачем по шагам:

| Шаг | Зачем |
|---|---|
| Приём файла (шара/форма/API/чат) | один вход для всех ролей; имя санитизируется (транслит, `_`), журнал приёма |
| Конвертация → Markdown | единый формат корпуса; PDF-сканы читаются VLM-OCR (Qwen3.8 vision) — точнее tesseract на русском |
| Индексация чанками (900 симв., перекрытие 150) + эмбеддинги bge-m3 | поиск по смыслу на русском и английском, кросс-лингвально |
| Ответ с цитатами и правилом «нет в документах — так и скажи» | проверяемость: врач/юрист сверяет не «мнение ИИ», а пункт документа |
| Глоссарий (`/srv/agents/glossary.md`) | аббревиатуры раскрываются ТОЛЬКО по словарю организации (ВК = врачебная комиссия), без додумывания |
| Дедуп по хэшу текста | один документ под двумя именами не создаёт противоречивых цитат |

## 2. Пути попадания файла в корпус (все ведут в один конвейер)

```
[Samba \\192.168.11.251\doctor]  _incoming ИЛИ корень шары
[Веб-форма дашборда /tasks]       кнопка «Загрузить» (+галка «создать задачу»)
[API]                             POST /api/inbox (multipart, X-Orch-Key)
[scp/cp на сервер]                /srv/agents/kb-inbox/
        │  (cron 5 мин / сразу)
        ▼
  задача doc-convert: шаг0 конвертация → /srv/agents/artifacts/task-N/*.md
                      шаг1 rag_index   → чанки+эмбеддинги в rag-svc (sqlite)
        ▼
  вопрос: задача doc-qa ИЛИ чат Open WebUI («создай задачу doc-qa: …»)
        ▼
  ответ с цитатами [doc#chunk] + строка «_источники: …_»
```

Имена: санитизация автоматическая — `Приказ о цитологии, гистологии.pdf` →
`Prikaz_o_citologii_gistologii.pdf` (транслит python, locale-независимый);
коллизии получают timestamp-префикс; исходное имя — в журнале приёма.

## 3. Три индекса в стеке — не путать

| | **Корпус оркестратора (rag-svc)** | **Knowledge Open WebUI** | **AnythingLLM (на рабочих станциях)** |
|---|---|---|---|
| Куда грузится | kb-inbox / шара / форма /tasks / массовый импорт | uploads в самом Open WebUI (Workspace → Knowledge) | локальные папки воркспейса |
| Кто отвечает | задачи doc-qa, **любые агенты через MCP** | чат Open WebUI с прикреплённой базой | десктоп-чат конкретного сотрудника |
| Эмбеддинги | bge-m3 через шлюз | bge-m3 через шлюз (тот же) | bge-m3 через шлюз |
| Хранилище | `/srv/agents/rag-svc/index.db` + `vectors.f32` (или Qdrant) | том `open-webui-data` (Chroma) | LanceDB в профиле приложения |
| Ранжирование | **гибрид BM25 + dense (RRF)**, фильтры по метаданным | dense | dense |
| Статус | **организационная база знаний** | интерактивный RAG в чате | личный блокнот |

**Правило (обязательное):** организационная база знаний — только rag-svc. Приказы, КР,
регламенты, СОП грузятся туда; Open WebUI Knowledge и AnythingLLM — личные/черновые
накопители сотрудника. Три индекса расходятся не из-за движка хранения, а из-за разных
чанкеров и метаданных, поэтому «синхронизация» между ними невозможна в принципе —
возможен только единый источник.

Доступ агентов к единому корпусу — через MCP-сервер `agents/mcp/rag-mcp-server.py`
(stdio, без зависимостей): инструменты `kb_search`, `kb_list_docs`, `kb_doc_chunks`,
`kb_stats`. Подключение и туннелирование — `agents/mcp/WINDOWS-MCP-GUIDE.md`.

Масштабирование корпуса (все клинические рекомендации, переход на Qdrant —
решение 28.10.2026, выполняется до массового импорта; замеры) — отдельный
документ **RAG-SCALE-PLAN.md**.

## 4. Дашборды и точки входа

| Адрес | Что показывает | Вход |
|---|---|---|
| `https://<IP>/` | чат + админка Open WebUI (Knowledge, Logs, группы) | учётка Open WebUI |
| `https://<IP>/tasks/` | **дашборд задач**: статусы, шаги, события, артефакты, гейты + **форма загрузки файла** | basic-auth `admin` / TASKS_UI_PASS (`/etc/orchestrator.env`) |
| `https://<IP>/ops` | здоровье стека: движок, KV, очереди, версии | ключ vLLM в браузере (localStorage) |
| `https://<IP>:8443/ui` | LiteLLM: ключи, лимиты, spend-логи | мастер-ключ / админ-учётка |
| `http://127.0.0.1:8500/api/...` | API оркестратора (tasks/registry/templates) | X-Orch-Key |
| `http://127.0.0.1:8502/...` | API корпуса: /health /stats /docs /query /index /index_bulk /delete /supersede /compact /reindex | loopback only |
| `Z:\` (\\192.168.11.251\doctor) | файловый вход/выход для отдела | samba-учётка |

Журналы: `/var/log/spark-llm/doctor-ingest.log` (приём из шары),
`journalctl -u agents-orchestrator -f`, `journalctl -u rag-svc -f`,
события задач — в `/tasks/` и в БД `agents_tasks`.

## 5. Как посмотреть, ЧТО в базе

```bash
# сводка: документы, специальность, версия, признак действующей редакции:
curl -s http://127.0.0.1:8502/docs | jq '{total_chunks, docs: [.docs[] | {name, specialty, doctype, version, current, chunks}]}'

# состояние корпуса: движок, латентность p95, распределение оценок, место, РЕКОМЕНДАЦИЯ:
curl -s http://127.0.0.1:8502/stats | jq '{backend,chunks,docs,superseded_docs,dense_resident,
  db_mb:(.db_bytes/1048576|floor), vec_mb:(.vectors_bytes/1048576|floor),
  p95_ms:.query_latency_ms.p95, top1_score, recommendation}'

# превью первых чанков документа:
curl -s "http://127.0.0.1:8502/docs/kr_arterialnaya_gipertenziya/chunks?k=3" | jq .

# всего чанков (здоровье индекса):
curl -s http://127.0.0.1:8502/health | jq -c .

# поиск с фильтром по специальности, включая устаревшие редакции:
curl -s -X POST http://127.0.0.1:8502/query -H 'Content-Type: application/json' \
  -d '{"q":"первая линия терапии","k":4,"filters":{"specialty":"кардиология"},"current_only":false}' \
  | jq '{search, filters, min_score, dropped, hits:[.results[]|{doc,idx,score,version,current}]}'

# чем отличается hybrid от dense на вашем вопросе (диагностика качества):
for m in hybrid dense bm25; do echo "== $m"; curl -s -X POST http://127.0.0.1:8502/query \
  -H 'Content-Type: application/json' -d "{\"q\":\"индапамид дозировка\",\"k\":3,\"mode\":\"$m\"}" \
  | jq -r '.results[]? | "\(.score)\t\(.doc)"'; done

# прямой sqlite-срез (для админа; схема v2):
python3 - <<'PY'
import sqlite3
c=sqlite3.connect('/srv/agents/rag-svc/index.db')
print("по специальностям:")
for r in c.execute("select coalesce(specialty,'—'), count(distinct doc), count(*) "
                   "from chunks group by 1 order by 3 desc"):
    print("  ", r)
print("устаревшие редакции:")
for r in c.execute("select distinct doc, superseded_by from chunks where current=0"):
    print("  ", r)
PY

# векторы лежат ОТДЕЛЬНЫМ файлом (не в SQLite!) — это норма для v2:
ls -lh /srv/agents/rag-svc/          # index.db + vectors.f32 + bulk-journal.jsonl

# журнал массового импорта (что прошло, что упало, сколько страниц OCR):
jq -c 'select(.status!="ok")' /srv/agents/rag-svc/bulk-journal.jsonl | tail -20

# артефакты конвертации (исходные .md):
ls -la /srv/agents/artifacts/task-*/

# Knowledge Open WebUI (второй индекс): в UI → Workspace → Knowledge — список
# коллекций и файлов внутри каждой.
```

## 6. Операции над базой

| Операция | Как |
|---|---|
| Добавить один документ | любой путь из §2, либо `sudo bash scripts/13-add-doc.sh /путь/файл.pdf "вопрос"` |
| **Массовый импорт (все КР)** | `sudo bash scripts/19-import-clinrec.sh --dry-run` → прогноз; затем `--limit 20` → пилот; затем `--ocr never` и `--night-only` для сканов. Подробности и модель стоимости: RAG-SCALE-PLAN.md §6 |
| Обновить редакцию документа | загрузить новую версию, затем пометить старую устаревшей: `curl -X POST :8502/supersede -H 'Content-Type: application/json' -d '{"name":"старое_имя","by":"новое_имя","current":false}'`. **Не удаляйте** — она нужна для аудита «чем руководствовались в марте» |
| Вернуть редакцию в выдачу | `POST /supersede {"name":"...","current":true}` |
| Удалить документ | `POST /delete {"name":"..."}` (освобождённые слоты векторов переиспользуются) |
| Вернуть место после удалений | `POST /compact` — пересобирает `vectors.f32` плотнее; `/stats.fragmentation` подскажет, когда пора |
| Переиндексировать всё | `POST /reindex` — пересчитывает векторы из сохранённых текстов (нужно при смене `RAG_DIM` или модели эмбеддингов; час-другой GPU) |
| Наполнить Qdrant без пере-эмбеддинга | `POST /reindex {"use_existing_vectors": true}` — минуты, GPU не нагружается |
| Перейти на Qdrant | `sudo bash scripts/18-vector-store-qdrant.sh` (откат: `--rollback`) |
| Вернуться с Qdrant | `sudo bash scripts/18-vector-store-qdrant.sh --rollback` — SQLite остаётся источником правды, переключение мгновенное |
| Мигрировать корпус v1 → v2 | `sudo bash scripts/17-rag-v2-migrate.sh` (сначала `--dry-run`); откат `--rollback` |
| Править глоссарий | `sudo nano /srv/agents/glossary.md` → `systemctl restart agents-orchestrator` |
| Настроить чанкинг | `RAG_CHUNK` / `RAG_OVERLAP` в `/etc/orchestrator.env` → `systemctl restart rag-svc` → **переиндексация всего корпуса** (`POST /reindex`). Менять только ДО массового импорта |
| Откалибровать порог релевантности | `RAG_MIN_SCORE`; процедура — RAG-SCALE-PLAN.md §7.3 |
| Резервная копия | ночной бэкап `/root/backup/<дата>/agents.tgz` содержит index.db, артефакты и inbox. **`vectors.f32` намеренно исключён**: он пересобирается из index.db через `POST /reindex`. Том Qdrant — тоже пересобираемый индекс, берётся только при `BACKUP_QDRANT=1` |
| Самопроверка после любых правок | `/opt/rag-venv/bin/python research/test-rag-svc-v2.py --backend both` и `.../test-mcp-e2e.py` |

## 7. Ограничения и честные границы

- Сложные таблицы/формулы PDF → текст с раскладкой (VLM-OCR улучшает, но не идеален); графовый разбор (RAG-Anything) — апгрейд P2b.
- Ответы — черновики с цитатами; медицинские/юридические решения принимает человек.
- Персональные данные: в корпус и в шару `doctor` — только обезличенное/регламентное; карты пациентов — отдельный контур (не реализован, требуется решение по маскированию).
- `doc-qa` отвечает по топ-6 чанкам: очень длинные документы (>80 стр.) выигрывают от укрупнения `RAG_CHUNK` или дробления на темы при загрузке.
- **Русская морфология в BM25**: в SQLite FTS5 нет русского стеммера, поэтому лексическая ветка работает префиксным матчингом (`препарат*` → препараты/препарата). Супплетивные формы («человек/люди») и синонимы («инфаркт миокарда» ≠ «ИМ») она не ловит — их вытягивает dense-ветка bge-m3 и глоссарий. Полное решение — Qdrant с multilingual-стеммингом.
- **«не найдено» теперь может означать «найдено, но ниже порога релевантности»**: `/query` возвращает поле `dropped` и пояснение в `note`. Для диагностики temporarily передайте `"min_score": 0` в запросе.
- Автоопределение метаданных при массовом импорте (специальность, версия, коды МКБ-10) — эвристика. **Проверяйте на пилоте `--limit 20`**, а не на всём корпусе.

## 8. Мини-FAQ

- **«не найдено», хотя точно есть** → проверьте: `/docs` (документ в индексе?), качество .md-артефакта (глазами), формулировку вопроса; скан без текстового слоя до VLM-OCR мог пройти с ошибками — перегоните задачу doc-convert повторно.
- **две копии ответа с разными именами** → дедуп ловит только полное совпадение текста; разные сканы одного приказа = разные документы: удалите дубль `/delete` или пометьте в имени `_archive`.
- **файл пропал из шары** → он уехал в kb-inbox (это норма), журнал приёма покажет новое имя и task#.
- **кто положил файл** → requester задачи: `doctor-share` (шара), `inbox-upload` (веб-форма), `openwebui`/email (чат), `cli` (скрипт 13).
