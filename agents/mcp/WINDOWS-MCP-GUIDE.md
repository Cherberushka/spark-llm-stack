# MCP в AnythingLLM на Windows — полная инструкция

MCP (Model Context Protocol) даёт агенту «руки»: чтение/запись файлов, shell,
БД и т.п. **Критично понимать:** stdio MCP-серверы запускаются **на вашей
станции** процессом AnythingLLM — т.е. «управление ПК» = управление этой
Windows-машиной, Spark-сервер не затрагивается. (Remote-серверы по URL —
отдельный тип, ниже §8.)

---

## 1. Предварительные требования

1. **Node.js LTS** (MCP-серверы — это npx-пакеты):
   ```powershell
   winget install OpenJS.NodeJS.LTS
   # или установщик с nodejs.org
   ```
   Проверка (новый терминал!): `node -v` (≥20) и `npx -v`.
2. **AnythingLLM Desktop** свежей сборки (MCP-раздел появился в 2025+); если в
   настройках нет пункта MCP — обновите приложение.
3. Первый запуск каждого сервера скачивает пакет с npm → нужен интернет один
   раз на сервер. Можно прогреть кэш заранее: `npx -y @modelcontextprotocol/server-filesystem` (Ctrl-C после появления ошибок аргументов — пакет уже в кэше).
4. **Перезапустите AnythingLLM после установки Node** (приложение наследует PATH
   при старте).

## 2. Где настраивается

*Настройки экземпляра (шестерёнка) → раздел агента → **MCP Servers***
(в некоторых сборках пункт называется «MCP-серверы» внутри «Навыки агента»).
Там: список подключённых серверов, статусы, инструменты, и **JSON-редактор
конфигурации** (формат как в Claude Desktop: объект `mcpServers`).

## 3. Готовые конфигурации (Windows-синтаксис!)

На Windows надёжная форма запуска — через `cmd /c npx` (прямой `npx` часто
ломается: это `.cmd`-шим, а не exe).

### 3.1. Безопасный старт — только папки с документами

```json
{
  "mcpServers": {
    "clinic-docs": {
      "command": "cmd",
      "args": [
        "/c", "npx", "-y",
        "@modelcontextprotocol/server-filesystem",
        "C:\\Users\\ivanov\\Documents\\ClinicDocs",
        "C:\\Users\\ivanov\\Documents\\Protocols"
      ]
    }
  }
}
```
- Подставьте **реальные абсолютные пути** (`%USERNAME%` не раскрывается!);
- кириллица в путях допустима, обратные слэши в JSON — удвоенные (`\\`);
- сервер видит ТОЛЬКО перечисленные корни — это и есть песочница.

### 3.2. Полные «руки» — файлы + shell + процессы (только машины разработчиков!)

```json
{
  "mcpServers": {
    "desktop-commander": {
      "command": "cmd",
      "args": ["/c", "npx", "-y", "@wonderwhy-er/desktop-commander"]
    }
  }
}
```
Даёт агенту выполнение команд, управление процессами, правку файлов где угодно
на этой машине. Включайте осознанно: только персональная машина разработчика,
только с подтверждением опасных команд в чате. На общих ПК клиники — НЕ ставить.

### 3.3. Полезные дополнения

```json
{
  "mcpServers": {
    "web-fetch": {
      "command": "cmd",
      "args": ["/c", "npx", "-y", "@modelcontextprotocol/server-fetch"]
    },
    "mis-db-readonly": {
      "command": "cmd",
      "args": ["/c", "npx", "-y", "@modelcontextprotocol/server-postgres",
               "postgresql://readonly:ПАРОЛЬ@mis-server:5432/mis"]
    }
  }
}
```
- `server-fetch` — чтение веб-страниц (если разрешён внешний веб);
- `server-postgres` — доступ к БД МИС **только под read-only пользователем**
  (создаётся на стороне БД: `GRANT SELECT`); строка подключения не должна
  содержать write-права — это страховка от «агент удалил таблицу».

Полный конфиг = объединение нужных блоков в один `mcpServers`.

## 4. Подключение и проверка

1. Вставьте JSON → Save/Apply. Статус сервера: **connected** (зелёный), рядом —
   список обнаруженных инструментов (`read_file`, `write_file`, `execute_command`…).
2. В чате переключитесь в **агент-режим** (`@agent` / тумблер Agent) — обычные
   чаты инструменты не вызывают.
3. Тесты по возрастанию смелости:
   - «Перечисли файлы в папке ClinicDocs» (filesystem);
   - «Создай в ней test.md со списком этих файлов» (запись);
   - ТОЛЬКО для desktop-commander: «Выполни `systeminfo | findstr /C:"ОС"` и покажи вывод» — подтвердите команду в запросе агента.
4. Если инструменты не появились в агенте: проверьте, что сервер connected;
   что в *Навыках агента* не выключена группа инструментов; начните новый чат
   (инструменты подхватываются на старте сессии).

## 5. Те же серверы для Pi на этой же Windows-машине

Pi читает MCP из `%USERPROFILE%\.pi\agent\mcp.json` — тот же JSON:
```powershell
notepad $env:USERPROFILE\.pi\agent\mcp.json   # вставить блок mcpServers
```
В сессии Pi: `/mcp` — статусы серверов. Один набор серверов = общие «руки» для
обоих харнессов.

## 6. Безопасность (обязательный раздел)

| Риск | Мера |
|---|---|
| shell на общей машине | desktop-commander только на персональных машинах разработчиков |
| агент правит не то | filesystem-сервер с узкими корнями вместо commander; ценное — вне корней |
| случайные деструктивные команды | подтверждения в чате; в commander отключите auto-approve, если включали |
| секреты в конфигах | пароли БД — только read-only роли; не кладите мастер-ключи в env MCP |
| антивирус/EDR блокирует spawn npx | исключение для `node.exe`/каталога npm-кэша, либо корпоративный allowlist пакетов |
| аудит | всё, что сделал агент, видно в истории чата AnythingLLM + в логах LiteLLM (токены/время) |

## 7. Troubleshooting (Windows-специфика)

| Симптом | Причина / лечение |
|---|---|
| Сервер «failed to start / error» сразу | Node не в PATH у приложения → перезапустить AnythingLLM (или ПК); либо использовать форму `cmd /c npx` (§3) |
| `npx не является внутренней командой` в логах | Node ставился «только для пользователя», а AnythingLLM запущен из-под другой учётки → ставьте системно (winget) |
| Долгий старт первого подключения | npx скачивает пакет; далее из кэша — быстро |
| Кириллица/пробелы в пути → ошибки | пути одним аргументом в кавычках JSON как есть (`"C:\\Мои документы\\..."`) — не разбивайте на несколько args |
| Инструменты есть, агент их не зовёт | не агент-режим; или скиллы/инструменты выключены в «Навыках агента»; или старый чат — начните новый |
| Ничего не понять | логи: `%APPDATA%\anythingllm-desktop\logs\` (и вкладка Developer/Console в приложении); вывод самого сервера виден в статусе MCP-страницы |
| MCP работает, но медленно | каждый вызов = round-trip к модели; укрупняйте задачи («сделай X целиком»), а не по шагу в сообщении |

## 8. Remote-MCP (опция, не для старта)

AnythingLLM умеет и серверы по URL (SSE/streamable HTTP) — так можно вынести
MCP на Spark (например, файловый сервер над `/srv/pi-web`) и дать нескольким
станциям общие «руки» к серверным папкам. Требует проброса порта/маршрута в
Caddy и токена авторизации — делайте, когда появится реальная потребность в
общем серверном файловом агенте; по умолчанию держим MCP локальным.

## 9. Итоговый минимум для клиники

- Станции сотрудников: **ничего** (у них Open WebUI в браузере);
- Станции аналитиков/врачей-исследователей: AnythingLLM + filesystem-MCP на
  папку документов + bge-m3-воркспейсы;
- Машины разработчиков: AnythingLLM (+commander по желанию) И Pi с тем же
  mcp.json; ключи — персональные виртуальные из LiteLLM.

## 10. Изоляция: как дать commander, не отдав машину (конструктор границ)

Тумблеры «Навыки агента» AnythingLLM **не** ограничивают MCP-серверы: граница
живёт в конфиге сервера (слой 1) и в правах ОС (слой 2). Помните асимметрию:
ограничение папок у commander действует на файловые инструменты, но
`execute_command` (shell) папками не ограничивается — поэтому для жёсткой
границы нужен слой 2.

| Слой | Механизм | Закрывает |
|---|---|---|
| 1 | конфиг desktop-commander: allowed directories + blocked commands (rm, del, format, shutdown, reg add, powershell -enc…) | ошибки, наивные prompt-инъекции |
| 2 | отдельный Windows-пользователь-песочница с NTFS-доступом только к папке проектов; AnythingLLM/Pi запущены под ним | побег shell'а за пределы песочницы |
| 3 | подтверждения опасных команд в чате | остаточный риск, социальные инъекции |

Рецепт слоя 2 (PowerShell, админ):
```powershell
net user agent-dev * /add
# NTFS: D:\projects → Свойства → Безопасность: снять наследование,
# agent-dev = «Изменение», Users = только чтение
runas /user:agent-dev "C:\Path\To\AnythingLLM.exe"   # или смена пользователя в Windows
```
Каждый разработчик выбирает свою песочницу сам (папка/учётка) — сервер при этом
не затрагивается вовсе. Для экспериментов «полный shell напрокат»: Windows
Sandbox или VM на сессию.

## 11. Профили инструментов filesystem-MCP (минимизация промпта и ошибок)

Каждый включённый инструмент = его схема в промпте каждого агент-запроса
(~60–150 токенов) + кандидат на ошибочный вызов. Держите минимальный профиль:

**Профиль «Документы»** (аналитики, врачи-исследователи):
- ВКЛ: `read_text_file`, `read_multiple_files`, `search_files`, `list_directory`,
  `directory_tree`, `write_file`, `create_directory`, `move_file` (архивация
  устаревших версий КР), `list_allowed_directories`
- ВЫКЛ: `read_file` (deprecated-дубль), `read_media_file` (если не нужно
  «смотреть» картинки из папки), `list_directory_with_sizes`, `get_file_info`,
  `edit_file` (если поток «прочитал → создал новый файл»)

**Профиль «Разработка»** (машины разработчиков, filesystem-корни = репо):
- ВКЛ: всё из «Документов» + `edit_file`, `search_files`, `get_file_info`
- ВЫКЛ: `read_file`, `list_directory_with_sizes`
- Примечание: для кода обычно выгоднее Pi/Cline (свои файловые инструменты +
  LSP), filesystem-MCP оставляйте под документы.

**Профиль «Полный»** (desktop-commander, персональная машина, песочница §10):
- включается целиком; безопасность держится не тумблерами, а слоями §10
  (учётка-песочница + блок-лист + подтверждения).

Правило пересмотра: раз в квартал пройти по тумблерам и выключить то, чем
никто не пользовался (видно по истории агент-вызовов в чатах).
