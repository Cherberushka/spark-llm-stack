# Pi-агент на рабочих станциях — памятка для развертывания (RU)

## Как это устроено

```
 Рабочая станция (репозиторий, файлы, git — всё ЛОКАЛЬНО)
 ┌────────────────────────────────────────────┐
 │ Pi: читает/правит файлы, запускает команды │
 │     (с вашего подтверждения), LSP, git     │
 └──────────────┬─────────────────────────────┘
                │ только промпты/контекст задач (HTTPS/HTTP по LAN)
                ▼
   DGX Spark 192.168.11.251:4000 (LiteLLM) → Qwen3.8-27B
```

Код и репозиторий **не покидают рабочую станцию**; на Spark уходят только
запросы к модели. Весь трафик — внутри подсетей организации (192.168.8–11),
в интернет не выходит. У каждого разработчика — свой виртуальный ключ
(выдаёт админ в LiteLLM UI: `https://192.168.11.251:8443/ui` → Virtual Keys);
по ключу в логах видно, кто и сколько генерировал, ключ можно отозвать точечно.

## Установка — Linux / macOS

```bash
# 1) Pi
curl -fsSL https://pi.dev/install.sh | sh
exec $SHELL            # или перезапустить терминал (PATH)

# 2) Конфиг провайдера (готовый шаблон из этого каталога):
mkdir -p ~/.pi/agent
sed 's/<SPARK_IP>/192.168.11.251/' models.json > ~/.pi/agent/models.json
chmod 600 ~/.pi/agent/models.json

# 3) Ключ — в профиль (свой персональный, НЕ мастер-ключ):
echo 'export SPARK_LLM_KEY=sk-ваш-виртуальный-ключ' >> ~/.bashrc   # zsh: ~/.zshrc
source ~/.bashrc

# 4) Проверка
pi --list-models spark # ждём: spark  qwen3.8-27b  262.1K ...
                       # пусто → SPARK_LLM_KEY не экспортирован в ЭТОЙ оболочке
```

Автоматом то же самое делает `scripts/06-setup-pi.sh` (спросит IP и ключ).

## Установка — Windows

Два варианта (доки Pi: «Run Pi on Windows»):
- **WSL (рекомендуется)** — внутри Ubuntu как в разделе выше;
- **Нативно**: в PowerShell `irm https://pi.dev/install.ps1 | iex`;
  понадобится Git Bash (Pi использует bash для команд модели); конфиг:
  `%USERPROFILE%\.pi\agent\models.json` (тот же шаблон с заменой IP),
  ключ: `setx SPARK_LLM_KEY "sk-..."` (перезапустить терминал).

## Повседневная работа с локальным репозиторием

```bash
cd ~/projects/мой-репозиторий
pi --model spark/qwen3.8-27b        # Pi 1.x: слэш; ":high" — уровень thinking
```

Внутри сессии:
| Команда/действие | Назначение |
|---|---|
| просто текст задачи | «добавь эндпоинт X», «найди и исправь багу в Y» |
| `/model` | сменить модель/провайдера на лету |
| `/think` | режим рассуждений: **выкл** для быстрых агентных циклов, **вкл** для сложных задач (дебаг, архитектура) — экономия токенов 40–60% |
| Enter во время генерации | немедленно скорректировать текущий прогон (steer) |
| Alt+Enter | поставить follow-up в очередь |
| `/compact` | сжать контекст длинной сессии |
| Ctrl+C / выход | сессия сохраняется — можно продолжить позже (см. доки «Manage Sessions») |

Pi сам читает/редактирует файлы репозитория, запускает команды оболочки
(спрашивает подтверждение), использует LSP и git — всё локально.

### Настройка под проект

- **`AGENTS.md` в корне репозитория** — инструкции проекту (стиль кода,
  команды сборки/тестов, «не трогать каталог X»). Pi подхватывает автоматически.
- **Скиллы** — пользовательские (`~/.pi/agent/skills`) и проектные; готовый
  инженерный набор: github.com/mattpocock/skills (установка через skills.sh
  с флагом `-a pi`); дизайн-скилл: github.com/Leonxlnx/taste-skill.
- **MCP-серверы** — `~/.pi/agent/mcp.json` (например, доступ к тестовой БД).
- **Шаблоны промптов** — доки Pi «Create Prompt Templates».

### Скрипты и CI (неинтерактивно)

Pi умеет print-режим для shell-скриптов (см. доки → Reference → CLI;
проверьте точный флаг через `pi --help`) — например, генерация changelog
или код-ревью diff'а в git-hook/CI-джобе, который дёргает модель на Spark.

## Несколько разработчиков одновременно

Сейчас движок запущен с `--parallel 1`: параллельные запросы **встают в
очередь** (это заметно при 3+ активных агентах). Масштабирование:
1. поднять `--parallel 4` в `/etc/systemd/system/qwen38-llamacpp.service`
   (контекст делится на слоты: 160K/4 ≈ 40K на сессию — обычно достаточно)
   → `sudo systemctl daemon-reload && sudo systemctl restart qwen38-llamacpp`;
2. либо перейти на vLLM NGC-рецепт (concurrency 8 из коробки, runbook §6.2/Прил. А.1).

## Другие харнессы через тот же шлюз (если кому-то удобнее)

Любой OpenAI-совместимый инструмент работает с `http://192.168.11.251:4000/v1`
+ персональный ключ, модель `qwen3.8-27b`:
- **Aider**: `aider --openai-api-base http://192.168.11.251:4000/v1 --openai-api-key $SPARK_LLM_KEY --model openai/qwen3.8-27b`
- **Cline/Continue (VS Code)**: в настройках провайдера OpenAI-Compatible — Base URL и ключ — как выше
- **OpenCode**: конфигурация провайдера по его докам (baseUrl + apiKey)

Полная инструкция: [`agents/mcp/WINDOWS-MCP-GUIDE.md`](../mcp/WINDOWS-MCP-GUIDE.md).

## Проверка связи (если что-то не работает)

```bash
curl -s http://192.168.11.251:4000/health/liveliness          # шлюз жив?
curl -s http://192.168.11.251:4000/v1/models -H "Authorization: Bearer $SPARK_LLM_KEY"
pi --list-models spark                                         # провайдер spark виден?
pi auth check --provider spark                                 # чем Pi авторизовался
```
Нет связи → станция вне подсетей 192.168.8–11 (файрвол Spark) или не задан
`SPARK_LLM_KEY` (провайдер без ключа Pi скрывает → «No models available»).
Для headless-пользователей (agent-dev) ключ берётся командой из файла:
`"apiKey": "!cat /home/agent-dev/.llm_key"` — см. `models.headless.json`.
